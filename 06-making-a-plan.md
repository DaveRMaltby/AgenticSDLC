# Making a Plan

If code is cheap, the **plan** is where the real engineering happens. A good plan states what we're building, why, and how we'll know it's right, clearly enough that an agent can deliver it.

### Today: use `/plan`

Start any change of more than a few dozen lines with the **`/plan`** skill. Work through the plan with the agent *before* any code gets written:

- Agree on the scope, the approach, and the risks up front.
- Have an agent team review it for holes and improvements.
- Check the finished plan into source control alongside the code.

### Coming soon: collaborating on plans in GitHub

In a future session, I'll show a **company-approved approach** for collaborating on plans in GitHub using [**Markdown Comments**](https://md-comments.com/), created by Marat.

- Reviewers comment inline on the rendered plan.
- The comments are stored in the Git repo itself, so there's no separate tool to keep in sync.
- The same comments show up in your IDE, where your agent can act on them.
